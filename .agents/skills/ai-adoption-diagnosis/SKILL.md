# AI 采纳层级诊断

按 [八级判定表](references/adoption-levels.md) 评级。评级单位是**一类任务的实际用法或一次可观察的运行**，不是人、产品或团队的永久等级。多个团队分别判断。

1. 先界定任务、观察窗口以及要判的是已实现用法还是设计。优先使用用户给出的运行记录、产物或明确授权查看的应用区域；配置、职称和团队名单只能证明结构。没有运行证据时，给出条件判断或说暂不能定级，不主动扫描无关历史。
2. 从日志找出六个动作分别由谁做：触发、拆解、派工、跟踪或处置异常、验收、汇总。区分人批准关键权限或最终结果，与人亲自逐项协调。区分真实派工与角色扮演，区分多模型回答与多 Agent 的独立执行。
3. 用最能区分相邻级别的证据定级。自动接续已由人发起的任务不等于背景主动触发。人管多个独立长程 Agent 是 Level 7；主 Agent 在授权范围内实际管理下游 Agent 是 Level 8。固定流程中的编排也要有实际派工与收尾的证据。同一任务可同时有多个特征，不做平均分。
4. 区分一轮已证实、反复观察到和仅计划实现。日志里的 Agent 自报状态按“记录显示/某角色报告”表述，未独立核对不写成已验证产物。结论只覆盖看过的样本；隐藏日志中可能存在的人为介入记为未知。

## 交付

每类任务给出**层级与适用范围、1–3 条可追溯证据、与相邻级别的分界、仍缺的关键证据**。有混合用法时分别列出。必要时只问一个能改变评级的问题，例如“发起后由谁派工，失败时又由谁决定重跑？”不因评级更高就建议更高权限，不设置自动化或调用受评 Agent 来补造运行记录。
