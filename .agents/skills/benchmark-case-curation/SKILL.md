# 评测案例整理

用用户指定的材料或明确授权的历史范围。优先收录有明确验收结论、重复返工、或足以检测常规能力退化的任务；同一类重复失败挑有区别的代表样本，不以凑数量为目标。

- 把**执行者可见**的任务说明、最少必需输入及工具状态，与**仅评审可见**的预期结果、失败证据和验收项分开。删除密钥、个人标识和无关上下文；替换数据时说明哪些判断仍成立，无法等价脱敏时限制使用范围，不假装可以外发。
- 保留当时真正可用的输入。纠正、标准答案和修复后的文件不能混进基线输入，除非这些材料本来就是任务输入。开放任务用可接受条件和可替代结果，避免要求逐字复刻一次成功输出。
- 标记案例用途：用于讨论与调校，或保留作最终回归。不要同时用一条案例拟定改动并将其宣称为独立验证。记录最少来源定位、可复跑限制和仍依赖人工的检查。

交付一条或一组案例，最少包含：**ID、任务类型、简报、执行输入、执行约束、仅评审可见的预期与逐项检查、样本用途、脱敏或权限说明**。如需落盘，可用 `brief.md`、`inputs/` 和 `review.md`，遵从已有结构和已批准保存位置；未获准时只给草稿。不开启定时收集，不上传日志或附件。
