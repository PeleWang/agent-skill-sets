# 模型对比与回归验证

先说明本轮要回答的决策，锁定案例、验收检查和通过门槛。只需分析已有结果时不重新调用模型。用户要求执行时，先核对可用运行器、预算和每组材料允许使用的服务；没有获准的模型或数据权限就交付计划或离线评审，不外传材料。

| 比较目标 | 改变的变量 | 固定条件 |
|---|---|---|
| 为任务选模型或配置 | 模型，或明确定义的配置组合 | 案例、输入上下文、提示、可用工具及验收规则；不可等同时记录差异 |
| 验证 Skill 改动 | 原版与修订版 Skill | 同一模型和配置、执行输入、工具权限、验收规则；加入未用于修订的保留案例 |

1. 执行者只看任务输入，不看标准答案、过往纠正和隐藏检查。尽量隔离运行状态。记录实际版本或模型标识、配置、样本和运行次数。有限预算优先覆盖代表案例；对关键且不稳定的案例按同样次数复跑，声明单次样本的限制。
2. 优先用脚本验证可计算事实。同一个 Rubric 检查同一案例的各版本，主观项尽量隐藏候选名称与呈现顺序，评审和执行分开。争议、证据不足或高影响判断单独列出，必要时交给人复核。
3. 区分已完成、运行失败、证据不足和未运行。报告分母、必过项、失败例、耗时与实际或可核实的成本；缺失成本记未知，不用估计冒充实际。只有门槛达标的方案才比较成本和耗时；小样本、运行差异和重要回归用文字说明，不用汇总分掩盖。

交付逐案例对照、一条有适用范围的建议和未验证项。证据不足可以结论为「不切换／暂不合并改动」。不因推荐就切换运行配置或发布结果。
