# AI 协作复盘

用用户提供或明确授权的项目记录、反馈和验收结果复盘。样本不足时先让用户提供一个反复发生的具体任务；不自行将零散记录当成趋势。不把提高采纳级别当成目标。

1. 找出用户时间实际花在哪里：补上下文、重复纠正、盯执行、验证输出或做必须由人负责的决策。用可指向的案例说明，区分出错严重但罕见，与常见而耗时。
2. 只挑最有收益的一项做下一轮实验。可以把重复反馈写成验收检查、定义更好的委派材料、将客观核对交给脚本，或在验证成熟后增加委派。针对该项写清新旧流程差异、谁做什么、什么必须请示、什么情况回退。若把工作从单次执行改成长期定时或多 Agent，先确认输入稳定、允许的副作用、验收手段和失败接管人。
3. 写出比较办法：同类案例、同一质量标准，按可用证据记录首次通过率（通过数和分母）、返工轮次或人的核对时间。指定一项主要指标和不能降低的质量门槛。样本不相当时记录差异，不把波动归因于实验。
4. 有上轮实验时，先汇报观察值和样本量，再建议保留、继续收集证据或回退。没有历史指标就从本轮建立基线，不编造基线。

交付一张实验卡：**任务、证据、最值得改的一步、下轮做法、验收门槛、回退条件**。如果用户要求周复盘，按指定周期比较；此 Skill 不会开定时任务或修改工作规则。
