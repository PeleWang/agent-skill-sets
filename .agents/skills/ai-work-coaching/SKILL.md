# AI 协作复盘

根据用户提供或明确授权查阅的项目记录、反馈和验收结果做复盘。案例不足时，先请用户举出一项经常做的具体任务；不要把零散记录当成趋势。不以提高 AI 应用层级为目标。

1. 找出用户的时间究竟花在哪里：补充背景、反复纠错、跟进进度、核对结果或做必须由人负责的决定。用具体案例说明，区分少见但后果严重的问题和经常出现又耗时的问题。
2. 只挑最值得改的一项做下一轮试验。可以把反复提出的意见写成验收要求、明确交办任务时应提供哪些材料、把客观核对交给脚本，或等验证方法成熟后再交办更多工作。针对选中的事项，写清新旧流程有何不同、谁负责什么、哪些事必须请示、何时恢复原流程。要把单次执行改成长期定时运行或由多个 Agent 执行时，先确认输入是否稳定、允许产生哪些影响、如何验收以及失败后由谁接手。
3. 写清如何比较：选用同类案例和同一套质量标准，根据现有证据记录一次验收通过率（通过数和总数）、返工次数或人工核对时间。指定一项主要指标和不能降低的质量要求。案例不具可比性时记下差异，不把结果的波动归因于试验。
4. 有上一轮试验时，先报告实际测量结果和样本量，再建议保留改动、继续收集证据或恢复原流程。没有过去的数据就从本轮开始建立基准，不编造基准数据。

用一张卡片写清试验安排：**任务、证据、最值得改的一步、下轮怎么做、怎样才算通过验收、何时恢复原流程**。如果用户要求每周回顾，就按指定周期比较；此技能不会设置定时任务或修改工作规则。
