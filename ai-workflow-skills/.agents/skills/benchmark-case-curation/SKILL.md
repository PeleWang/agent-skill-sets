# 评测案例整理

使用用户指定的材料，或限于用户明确授权查阅的历史记录。优先收录验收结论明确、反复返工，或能用来检查常规任务是否做得比以前差的案例；同类问题反复出现时，挑选各有代表性的案例，不为凑数而收录。

- 把**执行者能看到**的任务说明、必需的输入和工具状态，与**只有评审者能看到**的预期结果、失败证据和验收项目分开。删除密钥、能识别个人身份的信息和无关背景；替换数据时说明哪些判断仍然成立，脱敏后无法保留原有判断依据时就限制使用范围，不将材料视为可以外传。
- 保留当时确实可以使用的输入。纠正意见、标准答案和修复后的文件不能混入用来建立基准的输入，除非这些材料本来就是任务所需的输入。开放性任务要写清什么样的结果可以接受、还有哪些替代结果，避免要求逐字照搬某次成功的答复。
- 标明案例用途：供讨论和调整，或留作最后的回归测试。不要一边用同一个案例制定改动方案，一边把用它得出的结果称为独立验证。只记录足以找到出处的信息、重新运行的限制和仍需人工完成的检查。

交付一个或一组案例，至少包含：**ID、任务类型、任务简报、执行所需的输入、执行限制、仅供评审者查看的预期结果和逐项检查要求、样本用途、脱敏或权限说明**。如需保存到文件，可用 `brief.md`、`inputs/` 和 `review.md`，沿用已有目录结构并保存到获准使用的位置；未获准时只提供草稿。不设置定时收集任务，不上传日志或附件。
