# AI 应用层级诊断

按 [八个层级的判断标准](references/adoption-levels.md) 评级。评级针对的是**一类任务中 AI 的实际用法，或一次有据可查的运行**，并不是给某个人、产品或团队定一个永久等级。涉及多个团队时，分别判断。

1. 先明确任务、要查看哪个时段，以及评估的是实际用法还是设计方案。优先依据用户提供的运行记录、成果，或用户明确授权查看的应用内容；配置、角色名称和成员名单只能说明团队如何设置。没有实际运行的证据时，说明在什么条件下属于哪个层级，或说明暂时无法定级，不主动查阅无关的历史记录。
2. 从日志中找出六个环节分别由谁负责：启动任务、拆分任务、分配任务、跟踪进度或处理异常、验收、汇总。区分人工批准关键权限或最终结果，与人工逐项协调。区分实际分配任务和角色扮演，区分让多个模型回答和让多个 Agent 独立执行任务。
3. 根据最能区分相邻层级的证据定级。自动继续人已启动的任务，不等于在后台自行启动新任务。人管理多个独立执行长期任务的 Agent 是 Level 7；主 Agent 在授权范围内实际管理其他执行任务的 Agent 是 Level 8。即使流程固定，也要有主 Agent 实际分配任务并收尾的证据。同一任务可同时符合多个层级的部分特征，不取平均分。
4. 区分只在一轮中得到证实、已在多轮中观察到和仍停留在计划中的情况。Agent 自己报告的进度要注明“记录显示”或“某角色报告”，未独立核对过的成果不要写成已验证。结论只适用于查阅过的案例；未看到的日志中是否有人介入，应标为未知。

## 交付

每类任务给出**层级和适用范围、1–3 条注明出处的证据、与相邻层级的区别、还缺哪些关键证据**。有多种用法时分别列出。必要时只问一个会影响评级的问题，例如“任务启动后由谁分配工作，失败时又由谁决定是否重新运行？”不因为评级更高就建议扩大权限，不设置自动化或调用接受评估的 Agent 来补造运行记录。
