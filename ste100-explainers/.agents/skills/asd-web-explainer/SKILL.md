# ASD Web Explainer

把要讲解的内容做成便于阅读、操作和分享的中文交互网页。严格按这个顺序进行：**先写英文讲解并制作网页，再按原文译成中文**。

## 触发与范围

用户要做以下任务时，默认使用这项技能，不必等用户明确要求 HTML：

- 读论文或理解研究结果。
- 学习概念，弄清其背后的机制。
- 理解代码、算法或执行过程。
- 比较技术方案及其取舍。
- 分析数据、实验或性能结果。
- 制订计划、安排资源或推演不同情形。
- 理解规则、判断条件或操作流程。

把讲解限定在用户当前问题的范围内。用户明确指定其他格式，或只要一句话或纯文本时，以用户的要求为准。这项技能不会把“解释代码”变成修改代码，也不会把“制订计划”变成执行计划。

## 1. 确定内容与证据

沿用已明确的读者、目标、讲解深度和提纲。不清楚次要偏好时，按合理的默认方式处理，并简单说明；关键资料会影响结论时，先向用户确认。用户的相关指令要求先确认提纲时，应在写正文前确认；已经有明确提纲，或用户已经确认过时，不要重复询问。

阅读用户提供的论文原文、代码、数据或规则。需要外部资料时，优先使用论文原文和官方文档，保留原始出处的链接，以及版本、日期或实验条件。区分资料中已证实的事实、推断、假设和模拟数值。

分析数据时，用实际提供的数据计算结果。演示代码时，以核对过的执行过程或注明是模拟的结果为依据。比较方案时，说明适用条件和各自的取舍。推演计划时，注明对工期、资源和依赖关系的假设。没有实际资料时，可以制作教学示例并明确注明，不能把它当成用户的真实数据来展示。

## 2. 完成 ASD-STE100 英文解释

先写英文正文和界面上所有的英文文字。围绕用户要理解的关系、过程或判断来讲，不把固定的论文模板套用到其他场合。

采用 [ASD-STE100 官方标准](https://www.asd-ste100.org/STE_downloads.html) 的写作原则。可依据已合法取得的副本或官方公开资料，核对相关规则和词表。至少遵守以下可以核查的要求：

- 描述性句子最多 25 个英文单词；操作指令最多 20 个。
- 一个句子表达一个核心意思。一个段落讨论一个主题，最多六句。
- 用主动语态，表达要明确，时态要简单。避免连续使用进行时，也避免不必要地连用多个名词。
- 同一概念使用同一术语。按规定的词性和含义使用获准词汇，并遵守 technical nouns / technical verbs 的使用规则。
- 正文不用分号。这项要求不限制 JavaScript 等代码的语法。
- 技术名词要用得准确，并在正文中给出定义。不能为了缩短句子而删去影响理解的条件。

没有核查完全部规则和获准词汇表时，在交付说明中简要注明：写作时采用了 ASD-STE100 的原则，但未验证是否完全符合标准。不要声称已经通过合规认证。ASD-STE100 是英语标准，不声称后续的中文译文符合这一标准。

## 3. 制作美观而且便于理解的交互网页

先完成英文版网页，再开始翻译。选择适合内容的交互方式，不限定框架、布局或交互功能的数量：

| 内容 | 可用的交互方式 |
| --- | --- |
| 概念与机制 | 调整参数，观察计算结果或关系如何变化 |
| 代码与算法 | 逐步执行，显示变量、调用栈或数据结构 |
| 技术方案 | 调整需求和限制，根据所得结果进行比较 |
| 数据分析 | 筛选数据、查看异常、查找支持结论的数据 |
| 计划 | 调整工期或资源，查看依赖关系和瓶颈 |
| 规则与流程 | 输入具体情形，查看适用条件和处理路径 |
| 论文 | 根据论文的核心机制、实验和局限，选择上面合适的方式 |

每项交互功能都必须有助于回答一个具体问题，并确实更新计算、图示或结果。所有模拟数值和简化模型都要清楚注明。注意力图等教学图示不能当作对真实模型的测量结果，也不能当作完整的因果解释。

采用层次分明的字体设置、充足的间距、便于阅读的对比度和简洁的配色。让读者能直接看到必要的正文和主要结论。使用语义化 HTML、原生按钮和输入控件以及无障碍标签，并支持键盘操作和减少动态效果的设置。较长的中英文术语都应能在窄屏上自然换行。

默认生成一份可以单独打开的完整 HTML 文档，内嵌 CSS、JavaScript 以及必要的数据和图形。离线阅读和交互不能依赖 CDN、远程字体、API、外部图片、本地服务器或其他资源文件。指向论文原文等资料的外部链接可以保留。计算应当能在本地实际运行；不要加入无助于理解的动画或无关功能。

## 4. 忠实翻译成中文，保留英文名称

英文内容和交互功能完成后，再逐段翻译正文、标题、导航文字、控件文案、动态提示、图注和无障碍说明。保留英文版的信息、顺序、条件、公式、例子和交互中的计算；不能另写一篇中文讲解来代替翻译。

下列内容保留英文原文，即使已有中文译名：

- 论文、文章和作品的正式标题。
- 作者用英文命名或提出的概念、方法、架构、算法等的名称。
- 只用英文表达或没有可靠中文译名的术语。
- API、代码标识符、公式符号、数据字段、专有名称及缩写。

例如保留 `Attention Is All You Need`、`Transformer`、`Scaled Dot-Product Attention` 和 `Multi-Head Attention`。一般说明、常用名词和操作提示使用中文。按英文正文翻译术语的定义，不另行改写或补充解释。技术名词的来历不明时，保留英文拼写，不声称该论文首次提出这个术语。

不要翻译或更改程序选择器、元素 ID、变量、函数和运行逻辑。原文例子、代码和数据值中的英文，按例子要表达的意思保留。设置 `lang="zh-CN"`，只为中文和较长的英文名称作必要的排版调整。

## 5. 核对与交付

检查关键事实是否和原始资料一致，英文名称、数值、公式和中文译文是否有遗漏或偏离原意。核对中英文版的章节、段落和示例是否一一对应。

在浏览器中检查主要交互功能和至少一个边界情况。对数值演示，另行计算以核对结果。检查窄屏和桌面上的布局、键盘操作、是否有运行错误，以及能否通过 `file://` 离线打开。修复检查中发现的问题，不重复已经检查充分的项目。

将最终的中文 HTML 保存在本次任务允许使用的目录中，提供可以下载或打开的文件链接。不能只给 HTML 代码块、截图或临时 localhost 地址。分享文件时不必运行服务器。英文稿作为底稿保留；用户要英文版或 Markdown 时，再提供相应文件。默认只生成一个版本 B，不另外生成作为对照的普通讲解版本。

遵守当前的文件权限和用户授权，只改为完成任务必须改动的文件。用户没有要求时，不发布网站、不上传数据、不向他人发送文件。最后用中文简要说明文件的位置、用途和实际检查结果；制作过程放在回复中说明，不写进网页正文。
